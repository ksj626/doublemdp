# BDPO provenance and implementation audit

The implementation-faithful reference is [FlowRL](https://github.com/typoverflow/flow-rl/tree/bae22f4cad3f9ce0a220aceb877b0e979de89808), pinned at `bae22f4cad3f9ce0a220aceb877b0e979de89808`, with the MIT license and copyright retained in `third_party/flow-rl/LICENSE`. The paper reference is [arXiv:2502.04778v2](https://arxiv.org/html/2502.04778v2), revised 2025-05-29, including Appendix B. This current repository is a later modular library, not the exact paper snapshot. Maintained source contains only the necessary algorithm/network/data components, not the library's logging, dispatch, environment, or unrelated algorithms.

## Learning semantics

Behavior pretraining updates the behavior network and behavior EMA. `prepare_training` copies behavior **EMA parameters** into actor and actor target, without copying the behavior optimizer. During RL each call updates Q0 and Vt, applies critic EMA, and then (after the warmup, every fifth update) updates actor, actor EMA, behavior and behavior EMA, in that order. The actor therefore consumes the newly updated critic targets. Behavior continues learning during RL. Cosine schedules advance by each optimizer’s own update count; the actor schedule therefore advances only on delayed actor updates, not every global RL update. The behavior EMA gate in RL uses the fixed `_n_pretraining_steps` counter, as upstream; with the official `ema_every=1` it is always true.

Outer target: evaluate target Q0 on complete actor-target paths at next states; reduce candidate values before the ensemble reduction; subtract `eta * sum_t mean_candidate sum_action penalty`; multiply the resulting future value by the **environment** discount and bootstrap mask, then add saved reward. With max-Q the outer Q candidate reduction is max, whereas the path penalty remains a candidate average. This mixed reduction is preserved. Inner target: one reverse transition from a corrupted dataset action, target Vt at `t-1` except at `t=1`, where target Q0 supplies the boundary; subtract the current step penalty. There is **no environment discount per inner step**. Inner/actor candidate reductions are means, even if outer max-Q is enabled. `lcb` means ensemble mean minus rho times population standard deviation, after candidate reduction.

The one-step actor objective differentiates only its local reverse transition and its analytic epsilon discrepancy, using frozen target critics and behavior. Its training input is a forward-corrupted dataset action, not a sampled full policy trajectory. Full paths in the outer target are not an actor backpropagation graph.

The DDPM schedule is `beta_t = 1 - exp(-0.1/T - .5*(10-.1)*(2*t-1)/T**2)`, with index zero inserted. Approximate posterior variance is beta, not the exact posterior variance. DDPM clips predicted clean x0 when configured, then computes the posterior mean; intermediate noisy latents are not clipped. The final t=1 transition adds no noise. Both full and one-step sampling preserve this endpoint rule. The epsilon penalty is `0.5 * beta_t / alpha_t / (1-alpha_hat_t) * (eps_actor-eps_behavior)^2`, summed across action dimensions. This is the analytic Gaussian mean KL for the unclipped, beta-variance transition. **Caveat inherited from official code:** at the deterministic final step it is a finite epsilon-space penalty, not the KL of two unequal point masses; with clean-sample clipping it does not generally equal KL computed from clipped transition means. These conventions are preserved, not silently corrected.

Native Vt represents remaining current-generation regularization plus the regularized outer Q0 boundary. Q0 includes future environment-step path penalties. Ensemble pessimism and nonlinear candidate reductions further change the represented quantity. Consequently native values are not labeled unregularized Monte Carlo `Q^pi`. A single-candidate continuation returns both actions and, optionally, accumulated native remaining-generation penalty. It does not by itself estimate future outer-policy penalties. Best-of-N task performance is separate, and all candidate chains and selection indices are retained in traces.

## Profiles, history, and discrepancy decisions

- `official_code` uses the D4RL YAML **plus task overrides from `scripts/d4rl/bdpo.sh`**. Halfcheetah: eta .05, rho .5; hopper: eta .2, rho 2 (20 critics for medium, 10 otherwise); walker2d: eta .15, rho 1. Antmaze uses gamma .995, max-Q, Q0 layer norm, four 512-wide actor layers, behavior LR 1e-4, rho .8; eta .5/.2/1 by maze size. The script uses antmaze **v0**, while one paper table row says umaze-v2; Appendix A and public commands support v0.
- D4RL uses 2M pretrain + 2M RL updates, 50k warmup, 256 batch, 5 diffusion steps, actor 256x4 and critic 256x3 for locomotion, 10 target candidates. Evaluation selects highest mean-ensemble Q among 10 samples, except `antmaze-umaze-diverse-v0` uses one sample. Original evaluation is 10 episodes for locomotion, 100 for antmaze, every 50k updates; the public script seeds are 0–4. Locomotion rewards are multiplied by 1000/(max episode return − min episode return), computed after timeout-row removal. Antmaze rewards are multiplied by 100. Action clipping is 1e-5 inside [-1,1], and observations are not normalized.
- `toy_official_code`: pinned toy YAML, eta .05, rho 0, 100k pretrain + 100k RL, 5k warmup, batch 512, 50 DDPM steps, no clipping, one-candidate evaluation.
- `toy_paper_eta`: same **current-code** toy architecture/budget but eta .06 as Appendix B.2. This is deliberately not called exact figure reproduction: the appendix says it inherits D4RL settings aside from listed exceptions, while the later public toy YAML has a different budget. A 2M+2M paper-budget candidate must be configured and labeled separately if run.
- `toy_original_task_reduced_compute`: `configs/bdpo_8gaussians_sanity.json` retains original 8gaussians generation, 50 steps, .06 eta, rho 0, batch 512 and no clipping. It explicitly reduces actor/critic width to [64,64], time dimension to 16, ensemble and target candidates to 2, pretrain to 2k, RL to 5k, warmup to 500. These are completed sanity experiments if executed, not paper reproduction.
- `ogbench_port` and contextual-bandit/maze diagnostics are new tasks. No claim of original BDPO OGBench reproduction is made. Reward scales and budgets belong to their explicit run configs; no held-out tuning is implicit in `default_config`.

History audit inspected commit `9e8c667` (2025-05-25, “finalize bdpo”), `0b49ad2` (2025-11-09, initial toy addition), `e46aff2` (2025-11-10 toy update), and the current snapshot. Behavior continued updating during RL already in the May 2025 commit; freezing it would be a deliberate algorithm change. The current `ScalarCriticWithDiscreteTime` time MLP is [128,64] for 64-dimensional embeddings; May's `CriticT` used [64,64]. Later modular critic refactoring therefore matters beyond file names. Toy configs were added after the paper. Paper Figure 4 uses DDIM for visual illustration, whereas the pinned toy default and our native trace artifacts use DDPM; the plots therefore do not claim exact figure reproduction. We retain current code semantics and record those historical differences.

## Validation and execution

`tests/test_bdpo.py` imports the unmodified pinned BDPO/reference modules (skipping only eager import of unrelated algorithms). It supplies identical seeds, parameters and batches, compares initialized parameters, pretraining and RL losses, optimizer states, RNGs and EMA parameters, full sampler paths, one-step actor gradients, and all schedule types. Additional regressions test KL coefficients/gradients, reduction order, the absence of inner discount, terminal outer targets, final-step noise removal, trace/action identity, pretraining handoff, delayed updates, full checkpoint resume, readonly offline input arrays, original toy draw identity, and D4RL boundary versus bootstrap semantics. Float32 parity tolerance is atol 2e-6, rtol 2e-5 (same JAX/Flax backend).

The executable `python -m doublemdp.agents.bdpo_experiment` stores dataset checksum, configuration, device, counters, no-online-interaction/no-oracle-training-query declarations, JSONL losses, synchronized update timings, complete checkpoint plus sampler RNG, and status. `--resume` preserves optimizer schedules and random streams. Original toy evaluation exports samples, raw native traces, plotting arrays, PNG/PDF and MP4 with GIF fallback. The analytic reward and behavior density are used only for dataset generation and evaluation. Final checkpoint is the selection rule.

Actual run outcomes and resource limitations belong in run JSON files and the root `RESULTS.md`; this audit does not assert that planned budgets have completed.


## Measured numerical corner and distinct correction

A reduced two-critic original-toy run produced non-finite gradients during RL. An independent fixed-input reproduction shows the source of a plausible failure: with exactly equal ensemble values, JAX differentiates `mean(v) - 0 * std(v)` to NaN because the standard-deviation derivative is undefined at zero variance. The unchanged pinned `q_target="lcb", rho=0` path is retained for official-code profiles and parity. The separately named `q_target="mean"` numerical profile directly computes the candidate-reduced ensemble mean. It has the same mathematical zero-rho objective, but avoids evaluating that undefined derivative. Runs that use it must be labeled `stable_zero_rho`; it is not silently enabled in existing configurations. Full ten-critic short-budget original-toy seed 0 ran finite under the unchanged official LCB path. Non-finite runs are failed and their endpoint summaries invalid, not completed reproductions. The standalone runner now fails immediately when any loss/metric is non-finite and rejects non-finite evaluation actions.
