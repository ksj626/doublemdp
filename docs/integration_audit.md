# Final harness integrity review

These infrastructure changes preserve the native learning kernels and the OGBench sequence distribution. They apply to newly started processes; already running representative experiments keep the code loaded at their start.

| Failure caught | Fix and focused regression |
|---|---|
| A sidecar changes a reward layout, coverage-gap interpretation or shaping semantics while numeric arrays stay identical | Sampler checkpoints now include a canonical metadata digest, checked during resume and evaluation. Numeric array checks remain separate. Historical checkpoints lacking the new digest retain compatibility; their old metadata identity cannot be reconstructed retroactively. |
| Evaluation reloads a different local dataset from the same path | `evaluate.load_run` validates the dataset against the checkpoint sampler before restoring the agent. |
| A trainer replaces `checkpoint.pkl` between evaluation loading it and hashing its path | `load_checkpoint(with_identity=True)` hashes the same open file descriptor used to load the state. The regression replaces the path mid-load and confirms identity remains attached to the loaded snapshot. |
| An atlas cannot regenerate after the training dataset moves | Maze coverage observations are stored in `plot_inputs.npz`; bandit plots no longer reopen an irrelevant training dataset. New metadata includes exact checkpoint SHA256 and dataset arrays SHA256. Selected RQL bandit/corrected-maze artifacts were upgraded and regenerated from saved inputs. |
| A future, currently inactive 100M shard changes between interruption and resume | Sharded sampler state includes a fingerprint of all verified shard paths, contents and transition counts. Relative record paths are resolved against the manifest location. |
| A smaller, duplicate or mislabeled dataset is presented as 100M | Tests verify rejection of repeated paths, identical contents under different filenames, incorrect per-shard counts and incorrect total counts. Validation partners and all 100 distinct train files remain required. |
| Dense shaping uses a different environment discount than the learner | The existing gamma guard is regression tested before agent creation. |
| Re-enqueueing a job ID silently ignores changed hyperparameters, or two IDs write the same run directory | Queue insertion now rejects these collisions while preserving idempotent insertion of an identical configuration. |
| A displayed resume command uses the status tool's Python instead of the tested worker environment | Commands, environment variables and working directory are recovered from the actual stored launch record. No direct resume command is claimed before a checkpoint exists. |
| Extending a completed run fails before saving and leaves its old complete status visible under a larger budget | The trainer writes running status with the restored step before the next update, rejects budgets below that step, and restores process signal handlers on success or failure. |
| A resumed download silently accepts changed local bytes | Existing downloader provenance, when available, is checked against source URL, byte count and SHA256 before reuse. Files predating downloader provenance still receive loader-time dataset checksums; no unavailable upstream checksum is invented. |

The supervisor proactively blocks pending jobs whose standard train/validation download identities or complete 100M manifests fail verification. It checks actual bytes and transition counts, caches successful checks for quiescent files by filesystem identity for at most one hour, and releases data-blocked jobs only after verification passes. Writes younger than two seconds bypass the cache because filesystem timestamps can be coarse. Metadata-hidden in-place edits are not guaranteed to be detected immediately; expiry forces fresh byte checks. The 100M loader and checkpoint-resume validation provide additional independent identity checks. This stricter queue gate requires download provenance even though the standalone loader supports legacy files. Atomic manifest publication and guarded queue updates prevent partial downloads and simultaneous claims from changing active jobs.

Automatic orphan recovery requires a dead trainer, no live worker lease on its GPU, and a readable complete checkpoint matching the frozen queue configuration. Missing, corrupt or configuration-mismatched snapshots move the verified dead job to failed with a persistent manual-retry reason. Failed jobs and non-data manual blocks are never released by data readiness. Compare-and-swap checks PID, claim time and GPU and rechecks liveness before either recovery or failure; failed algorithms still require explicit inspection/retry. Singleton supervisor and GPU-worker leases prevent duplicate managed workers. A replacement supervisor adopts matching recorded worker PIDs. SIGHUP detaches the supervisor while preserving workers; SIGTERM/SIGINT request worker shutdown with checkpointing. The activated replacement adopted all six existing workers without interrupting training. Manual `sweep resume --retry-failed` remains an explicit retry operation, distinct from this conservative automatic recovery policy.

The full physical atlases use final checkpoints.
